## 0. 一页结论

| 问题 | 回答 |

## 1. E1：两个已证实缺口与修复

### 1.1 缺口一 —— 派奖只是标记，从未生效（**真 bug**）

修复前：`profit_opportunity.estimate_opportunity` 计算 `bonus_applied` 标记，
但**从未把派奖金额写进奖金表**。实测（修复前）：

```
bonus_applied(on) = True    bonus_applied(off) = False
E[gross] on = 58.190212     off = 58.190212     相同 -> True
```

**修复**：新增 `bonus_feasibility_v3.apply_bonus_to_table()`，
按 `prize_rules.LEVEL_CONDITIONS['era3']` 的奖级映射**真正叠加**派奖金额；
`profit_opportunity` 在 `bonus_applied` 时调用它。修复后：

```
E[gross] 派奖开(exact) = 86.4173    派奖关 = 58.1902    开 > 关 = True
```

### 1.2 缺口二 —— 整数元会截断半元

规则：`单注派奖奖金为当期对应奖级单注奖金的 50%`。六等奖 15 元 × 50% = **7.5 元**，
七等奖 5 元 × 100% = **5 元**。整数口径会把 7.5 变成 7。

**修复**：全流程改用 `Decimal`（`getcontext().prec = 60`），**禁止逐注截断**
（PLAN §4）。默认 `rounding="exact"`；`"official_pernote_floor"` 仅作**标注的敏感性**。

**四格目标值已验证**：

| 格 | R(3) | 构成 |
|---|---|---|
| A | **675** | 150 + 20×15 + 45×5 |
| B | **875** | 200 + 20×18 + 45×7 |
| C | **1125** | 225 + 20×**22.5** + 45×10 |
| D | **1470** | 300 + 20×27 + 45×14 |

### 1.3 关于官方的"7 元"与规则的 7.5 元（**已核实：7 元是展示取整**）

- **规则文本**（官方公告原文已存档）：`单注派奖奖金为当期对应奖级单注奖金的 50%`
  → 15 × 50% = **7.5 元**，条款中**没有逐注舍入的规定**；
- **官方接口的 `stakeAmount` 字段显示 7** —— 但这是**展示取整**，不是实际支付额：
  用 `totalPrizeamount / stakeCount` 反推，2026 派奖期（26050–26066）的
  六等奖派奖实际为 **7.499999 / 7.500000**（十余期全部一致）；
  上浮档期次为 **9.000000**（18 × 50% = 9，恰为整数）。

| 档位 | 规则推导单注派奖 | 官方 stakeAmount | 官方 总额/注数 |
|---|---|---|---|
| 基础档 六等奖 | 15 × 50% = **7.5** | 7（展示取整） | **7.499999** |
| 上浮档 六等奖 | 18 × 50% = **9** | 9 | **9.000000** |

**结论**：C 格的 **(3,1) = 22.5、R(3) = 1125 是正确值**；
`official_pernote_floor`（1115）是**读取展示字段造成的伪像**，
仅作为敏感性列为对照，**不代表另一种真实支付规则**。

| 格 | exact E[gross] | "展示取整" 对照 | 差（元/期） |
|---|---|---|---|
| C | 103.9299 | 103.7334 | −0.1965 |
| D | 126.7346 | 126.7346 | 0 |

## 2. E2：四格精确收益

固定奖档位 × 派奖的 2×2 设计（2026 七奖级规则）。
浮动奖取**同一期**一/二等奖的配对情景（`pairs_from_history`，保留联合关系），
此处展示 `pair_q0.50`；金额 `Decimal`，成本 132 元，税按公告 2024 年第 12 号。

| 格 | 档位 | 派奖 | R(3) | R(4) | E[税前] | E[税后] | **E[净收益]** | **ROI** |
|---|---|---|---|---|---|---|---|---|
| **A** | 基础 | 关 | 675 | 17,750 | 75.7028 | 66.1088 | **−65.8912** | **−49.9%** |
| **B** | 上浮 | 关 | 875 | 23,266 | 88.2624 | 78.1124 | **−53.8876** | −40.8% |
| **C** | 基础 | 开 | 1,125 | 26,625 | 103.9299 | 93.4464 | **−38.5536** | −29.2% |
| **D** | 上浮 | 开 | 1,470 | 34,899 | 126.7346 | 115.4172 | **−16.5828** | **−12.6%** |

**这是本轮最有信息量的结果**：把"上浮档 + 派奖"叠加起来，
每期期望亏损从 **−65.89 元降到 −16.58 元**（减少 74.8%，ROI 从 −49.9% 升到 −12.6%）。
**奖金条件是真实有效的**，只是仍不足以覆盖 132 元成本。

各命中档的课税状态（逐档枚举，未假定全局单调）：只有前区命中 4、5 两档的整组回收
超过 10,000 元起征点，两者恒被课税且为**全额 20%**；其余四档均免税。

## 3. E2：盈亏平衡边界

**结构性事实**：k=5 的整组回收 = `a + 20b + 45·c₅`（c₅=三等奖单注，与浮动奖无关），
且 k=4、5 恒被全额课税，因此 `E[净收益]` 对 `(a + 20b)` **严格线性**，
盈亏平衡边界是一条**直线**。

| 格 | 所需 `a + 20b` | 合法上限 | 代数可达 |
|---|---|---|---|
| A | **39,423,148.75** | 110,000,000 | 是 |
| B | **34,552,201.25** | 110,000,000 | 是 |
| C | **28,329,830.00** | 110,000,000 | 是 |
| **D** | **19,414,307.50** | 110,000,000 | 是 |

> ⚠️ 「代数可达」只说明解落在 `a ≤ 1000 万、b ≤ 500 万` 的合法盒内，
> **不代表会实际发生**。见 §4。

### 3.1 规则允许的乐观包络

一等奖与二等奖**同时**取各自封顶（a=1000 万、b=500 万 → `a+20b` = 1.1 亿）：

| 格 | A | B | C | D |
|---|---|---|---|---|
| E[净收益] | +173.92 | +185.93 | +201.26 | **+223.23** |

**包络全为正**，但必须注明：**两者能否同时触及各自封顶未核实**
（一等奖与二等奖的奖金总额来自同一"当期奖金额"的不同比例，
同时打满需要当期销售额与奖池同时极高）。**包络为正不构成可获得正期望的证明。**

## 5.0 对抗性复核发现的一个**仓库真实缺陷**（已修复）

复核裁判在核对官方原始响应时发现：**我的抓取工具把半元截断了。**

```
原始 API 响应（26050 期）：六等奖派奖 stakeAmount='7.50'
                          totalPrizeamount='4,521,202.50' = 602,827 × 7.50
tools/fetch_official_dlt.py::_num() 旧实现 int(float(s))  ->  入库成 7
```

**影响范围**（已逐行核对）：

| 级别 | 旧值 → 新值 | 受影响行数 |
|---|---|---|
| 九等奖派奖 | 2.0 → **2.5** | 95 |
| 八等奖派奖 | 7.0 → **7.5** | 95 |
| 六等奖派奖 | 7.0 → **7.5** | 12 |
| **合计** | | **202**（期号 21039–26065） |

**对既有结论的影响**：

| 对象 | 影响 |
|---|---|
| **V3 四格** | **0** —— 四格使用**规则表**（`bonus_feasibility_v3` 的精确 7.5），不读官方快照的固定奖 |
| D4/D5 的 500 期窗口（22145–26042） | 落入 **51 期**受影响；单组期望回收累计被低估 **+111.14 元**，摊薄到 500 期 = **+0.2223 元/期**。换算：`P1_a` 的净亏损会从 −48,522 变为约 **−48,411 元**（ROI −73.52% → −73.35%），**不改变任何方向性结论** |
| 更早的 `official` 口径历史结算 | 同类小幅低估；未回溯重算（按 E1「列影响范围而不覆盖旧结果」） |

**修复**：`_num()` 改为返回 `float`（**不截断**）；用**既有原始响应**重新解析
（不重新抓网），修正后的快照写入 `outputs/2026-10-13_5plus12_v3_bonus/data/`，
**未覆盖**任何旧快照。新增 3 项回归测试（`_num("7.50") == 7.5`、
快照保留半元、C 格 R(3)=1125 与官方实际支付一致）。

> 这个缺陷恰好说明 PLAN §4「用整数分或 Decimal 统一金额，禁止逐注截断」
> 的必要性：它不只在自建计算里成立，**也适用于读取官方字段**。

## 5.1 独立对抗性复核（3 个镜头 + 裁判）

本轮对三个承重结论做了**独立重算**（复核者不看被检验模块的实现，

| 镜头 | 独立复算对象 | 结果 | 裁判 |
|---|---|---|---|

| 2 | 四个盈亏平衡门槛 K（数值求根，换 4 个 b 值重复二分） | **完全一致**（四位同值，零点处 E[net] ≤ 2e-10） | **UPHELD** |
| 3 | 「103 期中为正的期数 = 0」、最优期、分格计数 | **一致**（逐期 max|Δ|=1.4e-14） | **UPHELD** |

**三个镜头全部通过裁判的对抗性复核（3/3 UPHELD）**，且裁判各自**独立重写脚本**
（未 import 被检验模块、未 import 复核者脚本；使用 Fraction 精确算术与官方原始 JSON）。

裁判指出并已被本报告采纳的三点：

1. **口径提示**：最近 718 期的最大 `a+20b`（19,210,020）来自 **24026 期，属 era2**；
   仅看 era3 的最大值为 **18,110,000**（已写入 §4.1 注）。
2. **半元截断缺陷**（见 §5.0，已修复）；
3. **"什么能推翻它"**：唯一能推翻"无正收益情景"的机制是**零假设失效**——
   需要把 `P(前区 5 中)` 相对提高约 **37%**，或把分布质量显著移向 `K ≥ 4`。
   这给下一步提供了一个**可证伪的明确门槛**（本轮未检验，也无法用规则数据检验）。

## 5.2 什么会改变本结论（可证伪条件）

| 机制 | 需要多大变化 |
|---|---|
| 提高前区 5 中概率（一等奖项） | **+37%** 相对提升（`p₅` 项贡献约 35.4 元/期，需再补 12.96 元） |
| 把分布质量移向 `K ≥ 4` | R(4) 已课税，需显著提高 `P(K=4)`（当前 4.62×10⁻⁴） |
| 未来浮动奖回到 2019–2021 水平 | `a+20b` 中位需从 10.5M 回到 ≥19.4M（历史上 1134 期有 63 期满足，但**都不在七奖级规则下**） |
| 出现新的奖金条件（新派奖/新档位） | 需**开奖前可得**的官方规则证据 |

> ⚠️ 第三行必须限定：四格实验只定义在 **2026 七奖级规则**上；
> 把 2019–2021 的期次套用同一四格是**无效外推**。
> 但若未来规则回到那种浮奖水平，结论确实可能不同——这属于 §6 的"未来规则变化"。

## 6. 局限与未解决项

1. **规则情景 vs 实测**：四格是**规则构造**，不是某期实测；
   人为组合的格子在本报告中一律标为"规则情景"。
2. ~~舍入口径未查明~~ → **已核实**：官方 `stakeAmount` 的 7 元是展示取整，
   实际支付为 7.5（`totalPrizeamount/stakeCount` = 7.499999）。
   主口径用精确值，无遗留不确定。
3. **封顶能否同时实现未核实**（规则包络的唯一依据）。
4. **调节基金余额条件未核实**：派奖可能因资金不足而"当期不再派奖"。
5. **分摊未建模**：本组中一等奖时新增 1 注一等奖与 20 注二等奖会稀释单注奖金，
   本轮**未建模**该分摊（缺当期奖级总额与原有中奖注数）。
6. **未做**：预算模拟、前瞻、实际投注、模型训练、全量回测。
7. 全部数据已被读取，**不构成样本外证据**。
